# Changelog

## fs-components 0.0.20

- **U3, the block editor is one continuous writing surface (user decision, 2026-11-14).** No field and no frame around a block any more: the page is one text on one text area, the blocks are the runs between blank lines. Enter in a paragraph makes the next block (a gap, the block itself stays unseen) and the cursor goes on; in a list, a quote, code and a table it stays in the block; Backspace at the start of a block joins it to the one above, in an empty block it takes the block away; `/` opens the block menu under the cursor. The title stays a field of its own above the surface. Cause of the finding "the content of the block left behind vanishes and comes back with the next key": every block had a text area of its own with its own state, rebuilt at every structural change (new block, measured width) and focus moving between them; with one text there is one state and a move is only the cursor moving. The class of fault is closed by design and by a test of the conformance collection (group "switching between blocks": after every edit all characters of the loaded text are still held, in order; a block editor that drops the text of the block it leaves is caught) and by a window test that moves through blocks with Enter, typing and Backspace while the window draws in between (`tests/notion_enter.rs`). **Not reproduced:** I could not make the old code lose the text in a picture or an in-process tree, so the cause named above is the mechanism, not a captured red test of the old code. `SourceEditor` is unchanged.
- Limits, stated plainly: the surface shows the Markdown of a block as typed (`# `, `- `), it is not a WYSIWYG view (that is the `RichTextEditor` to come); Backspace does not join into a list or a table above; the menu is under the line of the cursor, a floating panel as in Notion needs an overlay layer.

Deutsch:

- **U3, der Block-Editor ist eine durchgehende Schreibfläche (Nutzerentscheidung, 14.11.).** Kein Feld und kein Rahmen mehr um einen Block: die Seite ist ein Text in einer Textfläche, die Blöcke sind die Abschnitte zwischen Leerzeilen. Enter in einem Absatz macht den nächsten Block (eine Lücke, der Block selbst bleibt unsichtbar), der Cursor geht weiter; in Liste, Zitat, Code und Tabelle bleibt es im Block; Rücktaste am Blockanfang fügt ihn an den darüberliegenden an, in einem leeren Block nimmt sie den Block weg; `/` öffnet das Blockmenü unter dem Cursor. Der Titel bleibt ein eigenes Feld über der Fläche. Ursache des Befunds „der Inhalt des verlassenen Blocks verschwindet und kommt mit der nächsten Taste wieder“: jeder Block hatte eine eigene Textfläche mit eigenem Zustand, bei jeder Strukturänderung (neuer Block, gemessene Breite) neu gebaut, und der Fokus wanderte zwischen ihnen; mit einem Text gibt es einen Zustand, und ein Wechsel ist nur der Cursor. Die Fehlerklasse ist durch die Bauart geschlossen und durch einen Test der Konformitätssammlung (Gruppe „Blockwechsel“: nach jeder Änderung sind alle Zeichen des geladenen Textes noch da, in der Reihenfolge; ein Block-Editor, der den Text des verlassenen Blocks verliert, fällt durch) und durch einen Fenstertest, der mit Enter, Tippen und Rücktaste durch die Blöcke geht, während das Fenster zeichnet (`tests/notion_enter.rs`). **Nicht nachgestellt:** den alten Code konnte ich im Bild oder im Baum nicht dazu bringen, den Text zu verlieren; die genannte Ursache ist also der Mechanismus, kein erfasster roter Test des alten Codes. `SourceEditor` bleibt.
- Grenzen: die Fläche zeigt das Markdown eines Blocks, wie getippt (`# `, `- `), sie ist keine WYSIWYG-Ansicht (das ist der kommende `RichTextEditor`); Rücktaste fügt nicht in eine Liste oder Tabelle darüber an; das Menü steht unter der Zeile des Cursors, ein schwebendes Feld wie in Notion braucht eine Overlay-Schicht.

## fs-components 0.0.19

Findings of the user test of 2026-11-14 (Notion frontend "very good otherwise", Confluence frontend "usable, but not good"). Cause of all five: **this repository** (fs-components); fs-wiki reads and writes the text correctly (checked with the user's text, see the fs-wiki 0.0.12 CHANGELOG).

- **N1, Enter makes a new block at once.** Before, Enter put a line break into the same text area; the blocks were only cut at the blank lines when the page was saved and loaded again. Now Enter splits the block at the cursor, the text after the cursor is the new block below, and the keyboard goes there. In a list Enter carries the list on (`- `, `1. `, `- [ ] `, `> `); on an empty item it ends the list; in code (open fence) and in a table it stays a line break. Tested through the built widget (key event broadcast like the window runner does; the new block element is counted in the tree after the redraw); the counter-test with the new code switched off is red (`["first line\n"]` instead of two blocks).
- **N2, the `/` menu (first step: block types only).** `/` in a block opens a menu under it: headings 1 to 3, bulleted list, numbered list, to-do list, table, quote, code, divider. Typing filters (by name in the language shown, or by the Markdown marker), Up/Down/Enter/Esc and the mouse work; a choice writes the Markdown of the type into the block. The words are MessageFormat 2 files in German and English (`slash_menu/texts/*.mf2`, `SlashLabels`, `WikiLabels::slash`; `check_pairs` is tested). Pictures in both languages. Not in this step: content of other programs (embedding through the hub by capability, ADR 0019/0068), nested menus, a floating menu (it is a panel under the block and moves the text below it down).
- **C1, wrapping at the real width.** Cause: Blinc tells a text area its width only when the layout bounds differ from the ones stored in its state; an area that is built again starts with the default width (300 px) while the state still holds the old bounds, so it kept wrapping at about 250 px. The Confluence editor now makes the area forget its bounds when it is built (`measure_again`), and a Notion block is built with the width its place has (measured by the layout) and as many rows as its text takes at that width; the estimate of 75 characters per row (`rows_for`) is gone, so long blocks are no longer cut off. The offscreen renderer (`fs-components-render`) now does what a window does after the first layout (notifier for signals, rebuild of the areas that depend on them, layout again), so pictures show the second frame.
- **C2, table alignment.** `:---:`, `:---` and `---:` were read correctly by fs-text, but the table view ignored the alignment. Now centred and right-aligned columns are placed (header and cells). Writing back was never a problem (the text is kept as written).
- **C3, checkboxes.** Task items in lists (`- [ ]`, `- [x]`, GFM) are shown as boxes; they were before in the reading view, the raw Confluence editor shows the text as it is. **Our extension, not GFM:** a table cell that starts with `[ ]`, `[x]` or `[X]` (alone or with text after it) is shown as a box; GFM has task items in lists only. The text stays `[ ]` / `[x]`; saving writes it back unchanged.
- **Editor contract (decision of the user, 2026-11-14).** New crate `fs-components-editor`: trait `TextEditor` (a `Doc` of Markdown blocks in, only change operations `Op` out: insert, remove and replace a block; an editor never reformats), `Edit`, `diff`/`apply`, one **conformance collection** (`conformance::check`: the user's text and the GFM cases, round trip byte for byte, every edit visible as operations, an editor that reformats on its own fails), and empty extension points (`SourceModule`, `BlockModule`, `RichModule`, `Registry`; modules like hot plugins, ADR 0045; declared, not built). First two implementations, both passing the collection: `SourceEditor` (plain text; the editor of the Classic and Confluence frontends) and `BlockEditor` (Notion). `RichTextEditor` is later. Own operation types, because `fs-text` (repository fs-wiki) depends on fs-components and not the other way round; the wiki maps the operations to its model. Documentation: `docs/editor-contract.md`, `docs/editor-contract.de.md`.
- **W1, table cells wrapped too early ("Beschreibun|g", "Mal|sehen").** Cause (measured, not the guessed one): a plain cell was drawn as one rich-text element that Blinc sizes by its own measure, so a short cell broke at its last letter even when the column was wide; the same happened without any alignment. Cells now go through the text flow (`face.cell`), the width of a column follows the measured width of its longest cell on one line (bold in the head row) and is a share of the row with flex-basis 0, and the text of a centred or right-aligned cell is placed inside the full cell. Test with the table of the user test: no break while the column is wide enough, a narrow window wraps; the counter-test with the old code is red (5 lines instead of 3).
- **W2, the header row was outside the frame.** The background of the head row covered the top and side edges of the table frame; the head row has no background now (it stays bold, a line separates it). Test: a frame edge above the header text; red with the old style.
- **W3, "1 Seiten".** `WikiLabels::page_count_one` and `WikiLabels::pages_said(n)`: the side bar says "1 page" / "2 pages" (a program fills both forms; the wiki does so from an MF2 plural message). `fs_components_mf2::check_counts` renders a count message for 0, 1 and 2 and reports one and two said alike (counter-test: a message without selector is found); `contract/texts-check` finds count variables (`$count`, `$n`, `$number`, `$total`, ...) in a message without `.match` (selftest with both cases). No count text without a selector exists in this repository now.
- **W4, checkboxes can be ticked in the reading view** (all three layouts, also in table cells: our extension). `TextView::on_task` / `tasks_locked` / `count_tasks`, `DocumentSource::can_tick` and `set_task` (the source stores it as an ordinary change; a source without it refuses), `Reader::toggle_task`, `Labels::tasks_locked`. Without the right to change the page the boxes are drawn and locked (no click, a line under the text says why). Tests on the built widget with a mouse click through the router: the source gets exactly the calls of the clicks, no call without the right, a click on a box starts no edit in the Notion layout; the counter-test with the reader's code switched off is red. Evidence in the dossiers: Notion `features.md` lists to-do lists (checkboxes) and the key Ctrl/Cmd+Enter "Tick checkbox" (while editing); Confluence `features.md` lists action items among the autoformats. **Not evidenced:** that a click ticks a box in the reading mode of either product; it follows the instruction of the user test.
- **E1 to E5 (rework after the pictures, 2026-11-14).** E1: a table cell that starts with `- [ ]` or `- [x]` (a list marker typed in the cell, the form of the user test) is a checkbox like `[ ]` and `[x]`; the text stays as written (`cell_box`, one rule for the view and, in fs-wiki, for `tick_ops`; only the x changes when ticked). Not handled: a box after a line break inside a cell (fs-text keeps no line break in a cell; `<br>` stays text). E2: the boxes are the real checkbox component of the theme (`cn::checkbox`), the same function in a list and in a cell, no character imitation (a test reads the sources for it); a locked box is not disabled (a disabled box does not show that it is ticked) but puts a click back, with the cursor "not allowed". The offscreen renderer can draw with the default look of Blinc's own widgets, as a window has it (`Canvas::with_window_styles`; the picture of the workbenches uses it, the picture tests of `fs-components-pictures` do not). E3: `Labels::for_locale` and `WikiLabels::for_locale` (`MessageFormat` 2 files `fs-components-workbenches/src/texts`, German and English, plural page count); `Default` is the English of these files, so no fixed English words are left in `labels.rs` and `page_info.rs` (texts-check R2: 449 to 417); test: every field differs between the languages, the files are paired, the three layouts drawn in German differ from English. E4: Cancel (and Discard) of the editor are outline buttons, no longer as blue as Save (before, only fs-wiki 0.0.11 did this with a style rule); test: no primary-blue pixel under Cancel. E5: the side columns give way so the page keeps 360 px: the right panel of the Confluence layout goes first, then the left column (and the Notion sidebar) shrinks; test: the title is one line at 900, 700, 600 and 480 px; counter-test with the old widths red.
- Additive API: `BlockEditor`, `SourceEditor`, `contract`, `Step::BlockMenu`, `ReaderWidget::{block_texts, focused_block, focus_block, type_in_block, block_menu_open}`, `WikiLabels::slash`, `SlashLabels`.
- Limits, stated plainly: Shift+Enter is not a line break inside a block (Enter always splits; a line break inside a paragraph needs a list or a table); the checkboxes are shown, not clickable (a click on a block starts editing, as before); lines in the editors end up to one word before the right edge (Blinc measures the text about 4 percent wider than it draws it); the first frame of a block is as wide as its place without the measured width, the second has it; Enter and the arrow keys reach the editor as broadcast key events, proven in process (event tests and pictures), not in a real window; the contract knows blocks of Markdown source, not yet marks or the identity of a block (the wiki keeps those); text that is not in canonical form (several blank lines, no line break at the end) is normalised by the block editor, as before.

Doku: `docs/editor-contract.md`, `docs/editor-contract.de.md`.

## fs-components 0.0.18

- Umbau-Werkzeug (tooling for the frontend rebuild, ADR 0074): `contract/umbau/count` counts the fixed colours, spacings, sizes, radii, fonts, borders and opacities per crate and module, plus the class names outside the contract (state: `contract/umbau/STAND.md`, order of the groups: `PLAN.md`); `contract/umbau/tokens` writes the token list (`TOKENS.md`, `tokens.json`): scales per kind, the place of every counted literal, and the **18 new tokens** (spacing 1, border width 3, size 12, opacity 2) the conversion needs; both have counter-tests (`selftest`, `tokens_selftest`). Rules applied: Craft is the reference style, a tie takes the smaller step, opacity tolerance 0.05, wide single measures are `size` tokens. `Color::TRANSPARENT` and zero values count as nothing.
- New crate `fs-components-pictures` (test support, not published): draws blocks offscreen on the software Vulkan driver (lavapipe), compares pixel by pixel with small reference PNGs (`contract/umbau/bilder`, 76 KB), writes a diff picture on failure. Without lavapipe the tests skip locally and fail when `CI` is set.
- charts: tolerance per group because of the font on the runner. The chart text is set in the default sans of the machine (not the bundled JetBrains Mono), so the CI runner (Ubuntu, `fonts-dejavu-core`, `fonts-noto-core`) draws it differently from the machine of the references: CI run 43537722102 found 3723 (line) and 2787 (bars) different pixels. Reproduced here with only Noto Sans installed (3721 and 2785), so the font is the cause. CI run 43542886442 then showed the same for kanban. Groups that draw text in the system font have a tolerance: charts (`SYSTEM_FONT`: channel 64, 1 px, at most 900 of 64000 pixels = 1.4 %), kanban (`SYSTEM_FONT_BOARD`: channel 96, 1 px, at most 1600 of 124800 = 1.3 %), primitives (`SYSTEM_FONT_SMALL`: channel 64, 1 px, at most 35 of 19200 = 0.2 %); styles (colour strips) and render use `RASTER` (channel 4, no move, at most 12 pixels = 0.1 % of the smallest picture), because CI run 43552885270 found 3 pixels with a channel step of 1 in `render/text_craft` (rounding of an edge by the runner's lavapipe, even with the bundled font); measured here 0 pixels with both font sets, and a move of 1 px gives at least 128 pixels, so it stays red. Measured with the machine's fonts reduced to only Noto Sans or only DejaVu Sans (bwrap): every group passes with both; the highest counts are charts 621, kanban 1076, primitives 23 pixels. A move of 3 px, a wrong colour, an inverted and an empty picture still fail for every block (`tests/tolerance_counter.rs`; the margin is thin for primitives: 23 allowed-side against 42 for a 3 px move). The picture test now writes the diff picture and the drawn picture to `target/pictures-diff/<group>/` and names both in the failure text.
