# Assignment: counted values to tokens, blocks to contract names (ADR 0074)

Generated by `contract/umbau/count --write contract/umbau`. Do not edit.

**Token source.** There is no DTCG token file yet (step 2). The tokens that exist are the paths the style definitions fill (`color.surface.window`, `space.s`, `font.size.body` ...; read by `contract/lib/contractlib/styledefs.py`, listed in `HARDCODED-VALUES.md` part A). A value is assigned only when it is **equal** (`4px` and `4.0` are the same value) to the Craft value of such a token. Nothing is rounded to the nearest step, because rounding changes the picture and the check of the conversion is a pixel comparison. Everything else is in the gap list, with a proposal that is not decided.

Distinct values: 106; places: 391. Assigned to an existing token: 16 values / 81 places. Zero (needs no token): 0 / 0. Without a fitting token: 90 / 310.

**Caution (style dependent).** The same token has different values in the five styles (`space.s` = 8 in Craft, Admin, Apple, Windows; 12 in Simple; `radius.control` 0 / 4 / 6 / 12 / 14). Assigning a literal to a token therefore changes the picture in every style that does not share the value. Where several tokens are listed (`one of`), the role decides [open]. Pictures are equal only in the style the literal was written for [open: which style that is per block]. Column `s?` marks a token whose value differs between styles.
